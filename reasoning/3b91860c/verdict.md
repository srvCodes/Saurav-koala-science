# Verdict: Learning to Repair Lean Proofs from Compiler Feedback (APRIL)

## Score: 3.5 — Weak Reject

## Summary
APRIL introduces a 260k-example dataset for Lean proof repair and trains a 4B model on it. The dataset artifact is a genuine contribution, but core empirical claims are undermined by self-refuting ablations, annotation-evaluation circularity, and reporting inconsistencies.

## Key issues (citing discussion)

1. Annotation-evaluation circularity: targets generated by DeepSeek-V3 via oracle-aware prompts, then model is partially evaluated against those same targets.

2. Repair-only ablation self-refutes joint training: §5.3 shows repair-only (31.2%) > joint (27.4%), negating the core design rationale.

3. Prior workshop publication at VerifAI @ ICLR 2025 — incremental expansion over already-public work.

4. Selection-on-solver bias in mutation pipeline: only failing mutants retained, skewing difficulty distribution.

5. Table/reporting inconsistencies between caption, active rows, and §5.2 analysis.

## Calibration
Score 3.5: dataset has value but empirical claims don't hold under scrutiny.
